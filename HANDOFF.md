## Правила

1. **Начало сессии.** Прочитай этот файл целиком и в `TASKS.md` только раздел «Текущая очередь». `HANDOFF-archive.md` целиком не читай: ищи `grep -n '^### ' HANDOFF-archive.md` и по словам. План игры (`docs/plan/game-plan.md`, ~140 КБ) — только нужный раздел через `grep -n '^## '`.
2. **Взял задачу — сразу запиши** её в «Сейчас в работе» (кто, время UTC, задача, ветка, статус, следующий шаг). Обновляй после каждого значимого шага и обязательно перед остановкой. Устаревшие строки исправляй на месте, не оставляй рядом противоречащие.
3. **Ветки и PR.** Код — отдельная ветка `feature/<кратко>` или `fix/<кратко>` и PR в `main`. Коммитить часто; перед любой остановкой — коммит (незаконченное с пометкой WIP) и `git push -u origin <ветка>`. Сливает PR владелец, пока он сам не разрешит иначе. **Прямо в `main` без PR** можно только `HANDOFF.md`, `HANDOFF-archive.md`, `TASKS.md` и `docs/plan/game-plan.md` (банк идей) — отдельным коммитом без других файлов.
4. **Пиши факты:** команды и их результат, пути `файл:строка`. Не пиши «всё работает» без проверки.
5. **Никаких секретов:** не копируй сюда ключи подписи, токены, содержимое `.env`, данные игроков.
6. **Где что живёт:** этапы и их статус — `TASKS.md`; подробный план этапа — `docs/plans/NN-*.md`; архитектурные решения — `docs/decisions/`; здесь — только оперативное состояние.
7. **Экономия лимита.**
   - Отвечать владельцу кратко: итог и важное, без пересказа шагов; подробно — только по просьбе.
   - Вывод команд ограничивать: `tail`, `head -n 50`, `grep`; не выводить полные логи тестов и сборки.
   - Посильное — сначала локальной модели (п. 8); остальные механические задачи (поиск по коду, прогон тестов) — субагенту `test-runner` (Haiku) или `Explore`; задачи с суждением (архитектура, экономика, приёмка) — `architect`, `economy-auditor`, `code-reviewer`.
   - Независимые части работы запускать параллельно, а не одну за другой.
   - Здесь держать только текущее состояние и последние 5 записей журнала; старые переносить в `HANDOFF-archive.md` (новые сверху, заголовок `### ГГГГ-ММ-ДД — кто: что`).
8. **Локальная модель — обязательно для посильных задач.** Посильное — сначала локальной модели Qwopus3.6-35B на хабе владельца, а не самому и не платному субагенту. Claude ставит задачу, проверяет результат и отвечает за него.
   - **Посильные:** тексты интерфейса и ключи локализации ru/en по образцу; строки CSV баланса и имена по готовому описанию; черновики юнит-тестов GUT и Jest для уже описанного поведения; шаблонный GDScript и TypeScript по образцу из репозитория; описания коммитов и PR; краткие сводки логов и диффов; варианты названий и описаний для «Банка идей».
   - **Не отдавать:** `client/sim/` (детерминизм), серверную экономику и защиту (`server/src/economy/`, `validation/`), архитектурные решения, приёмку и ревью, регулярные выражения (на замерах модель в них ошибалась), задачи с входом больше ~4000 токенов (контекст модели 8192).
   - **Как вызывать:** OpenAI-совместимый API. Адрес хранится только локально, в `CLAUDE.local.md` как `LOCAL_LLM_URL` (адрес хаба в Tailscale, порт 8080), и в Git не попадает. В подсказке — только нужный фрагмент, без ключей, `.env` и данных игроков.
     ```bash
     curl -s --noproxy '*' -m 600 "$LOCAL_LLM_URL/v1/chat/completions" -H 'Content-Type: application/json' \
       -d '{"messages":[{"role":"system","content":"Отвечай только результатом."},{"role":"user","content":"<задача и образец>"}],"temperature":0.8}'
     ```
     Генерация идёт на процессоре, около 8–9 токенов в секунду, поэтому большие ответы ждать долго. Не держать на ней срочную работу; ставить таймаут; длинное дробить на части. Температуру держать около 0,8: на 0,2 модель в замерах ошибалась чаще.
   - **Проверка обязательна:** результат прогнать линтерами и тестами, сверить с правилами `CLAUDE.md`; ошибочное исправить самому. Не выдавать работу модели за проверенную без проверки.
   - **Если модель недоступна** (облачная сессия или задача по расписанию вне Tailscale, хаб выключен, таймаут): сделать задачу самому или субагентом `test-runner` (Haiku) и записать это в журнал одной строкой. Не ждать модель и не чинить хаб без поручения владельца.
   - **В отчёте и журнале указывать исполнителя:** «Qwopus (локально) + проверка Claude», «Claude», «субагент Haiku».
9. **Связь.** Если недоступен GitHub, Nakama, RuStore или другой сервис — сразу сообщи владельцу, не обходи блокировку и не ослабляй проверки.
