# 01. Ядро симуляции
Цель: забег из 10 волн с двумя шестернями (Пильная, Паровая) и двумя монстрами (Ржавчик, Скрипун) полностью считается в `client/sim/` без графики и детерминированно.
Раздел плана: «Ключевые механики», «Формулы и стартовый баланс», «Недели 1–2 — серый прототип» в `docs/plan/game-plan.md`; правила — `docs/design/core-rules.md`, разделы 1–6, 8.

## Шаги
- [ ] 1. `sim/fixed.gd`: умножение и деление ×1000, таблицы `SIZE = [1000, 800, 640, 512, 410]`, `DMG_MUL = [1000, 2400, 5760, 13824, 33178]`, `HP_MUL` (1.13ⁿ для n = 0..39) — тест: `tests/sim/test_fixed.gd` (значения таблиц совпадают с заранее посчитанными)
- [ ] 2. Данные: `data/balance/gears.csv` (Пильная, Паровая: урон, ударов за оборот ×1000, параметры режимов), `monsters.csv` (Ржавчик, Скрипун: HP₀, скорость, стоимость, урон Стене), `run.csv` (P = 8, Стена = 100, тики Реверса, клина, конвейера, паузы); `build_data.py` → `.tres` — тест: `make data` + `tests/data/test_data_load.gd`
- [ ] 3. `sim/grid.gd`: сетка 7×5, Сердце (3, 4), поставить / убрать / переставить, занятость, «заблокированная клетка» (для глыб и труб) — тест: `tests/sim/test_grid.gd`
- [ ] 4. `sim/power.gd`: обход в ширину от Сердца, шахматное направление с флагом Реверса, нагрузка `L`, `k = min(1000, P*1000/L)`, rpm с `size` и бонусом; пересчёт только при изменении сетки — тест: `tests/sim/test_power.gd` (10+ раскладок: цепочка, разрыв, `L > P`, Реверс)
- [ ] 5. Раскрутка 60 тиков после начала волны и после Реверса; Реверс — стоп 45 тиков, перезарядка 600 — тест: `test_spinup.gd`, `test_reverse.gd`
- [ ] 6. `sim/gear_runtime.gd`: фаза копится от rpm, «ударов за оборот» → события атаки; урон `base * dmgMul` — тест: `test_gear_phase.gd` (число ударов за 300 тиков при известном rpm)
- [ ] 7. `sim/monsters.gd` + поле боя: позиции в фиксированной точке, движение к Стене, зигзаг Скрипуна через `SimRng`, урон Стене, смерть, гайки — тест: `test_monsters.gd`
- [ ] 8. Пильная (↻ диск пробивает 3 цели по линии / ↺ диск у Стены) и Паровая (↻ конус и отбрасывание / ↺ облако −35% скорости); выбор цели детерминирован (сортировка по id при равенстве) — тест: `test_gear_saw.gd`, `test_gear_steam.gd`
- [ ] 9. `sim/wave_director.gd`: бюджет `10 + 4w`, состав по стоимости через `SimRng`, спавн, конец волны, пауза 450 тиков — тест: `test_waves.gd` (одно зерно → один состав)
- [ ] 10. `sim/run_state.gd`: Стена, гайки, конвейер (новая шестерня каждые 150 тиков, 3 слота, переполнение → +1 гайка), мерж (одинаковые тип и уровень → +1, максимум 5) — тест: `test_conveyor.gd`, `test_merge.gd`
- [ ] 11. `sim/sim.gd`: порядок тика строго по разделу 2 core-rules; журнал `[tick, action, args]`, `apply_input` с проверкой допустимости (недопустимый вход отбрасывается одинаково на клиенте и в валидаторе) — тест: `test_tick_order.gd`, `test_inputs.gd`
- [ ] 12. `sim/run_log.gd`: формат журнала из раздела 8, сериализация, хэш итогового состояния; `tools/determinism_check.gd` и 3 эталонных журнала в `tests/fixtures/runs/` — тест: `make determinism`
- [ ] 13. Простой бот и `tools/balance_sim.gd`: N забегов → JSON «на какой волне умирают» — тест: `make sim RUNS=100` создаёт отчёт в `tools/out/`

## Затрагиваемые файлы
`client/sim/*.gd`, `client/tests/sim/*`, `client/tests/fixtures/runs/*`, `client/tools/determinism_check.gd`, `client/tools/balance_sim.gd`, `data/balance/{gears,monsters,run}.csv`, `tools/build_data.py`

## Риски (детерминизм, сервер, производительность)
- Порядок вызовов `SimRng` — часть протокола: фиксируем в комментариях и эталонных журналах.
- Переполнение int64 в цепочках умножений ×1000 — делим после каждого умножения, тесты на максимальных значениях.
- Порядок обхода словарей и массивов: только массивы с явной сортировкой.
- Хук `determinism-guard.sh` блокирует `float`, `randf`, `Time` в `sim/`.

## Обучение игрока
Нет — интерфейса на этом этапе нет.

## Готово, когда
`make test-client`, `make determinism`, `make lint` зелёные; бот проходит 10 волн; `make sim RUNS=100` выдаёт отчёт.
