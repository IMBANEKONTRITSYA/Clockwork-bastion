# 06. Сервер: аккаунты и экономика
Цель: игрок входит в игру (гость, VK ID, Яндекс ID, Google, почта); кошелёк, инвентарь и прогресс живут на Nakama, каждая операция записана в журнал.
Раздел плана: «Техническая архитектура», «Стек технологий», «Недели 5–6»; ADR-002, ADR-003; правила `.claude/rules/server.md`.

## Шаги
- [ ] 1. Каркас `server/src/`: `RpcError` с кодами, проверка входных данных по схемам, обёртка «операция + запись в журнал» в одной транзакции — тест: `server/tests/errors.test.ts`
- [ ] 2. Схема хранилища v1: кошелёк (Латунь, алмазы, осколки, материалы), инвентарь, герои, скины, прогресс глав — тест: `storage.test.ts`
- [ ] 3. `economy/ledger.ts`: кто, когда, сколько, причина, идемпотентный ключ — тест: `ledger.test.ts` (повтор с тем же ключом не начисляет дважды)
- [ ] 4. `time.ts`: серверное время, сутки с 00:00 МСК (UTC+3) — тест: `time.test.ts`
- [ ] 5. Гостевой вход по устройству; `client/services/net/` — интерфейс сети + заглушка для офлайн-тестов (клиент Nakama для Godot — только после вашего согласия на зависимость) — тест: Jest + GUT на заглушке
- [ ] 6. Вход через Google: токен проверяет сервер — тест: поддельный токен → отказ
- [ ] 7. VK ID и Яндекс ID через custom-аутентификацию Nakama; токен проверяется через API сервиса — тест: мок HTTP
- [ ] 8. Почта и пароль; привязка нескольких способов к одному аккаунту; +100 алмазов за первую привязку, один раз — тест: `link.test.ts`
- [ ] 9. Удалённый конфиг (JSON в хранилище Nakama, с версией), RPC `get_config`, кэш на клиенте — тест: `config.test.ts`
- [ ] 10. Окно согласия на обработку данных (152-ФЗ), отметка согласия на сервере — тест: RPC + тест сцены
- [ ] 11. `client/services/meta_cache.gd`: клиент только показывает кэш, все изменения — через RPC — тест: GUT «нет записи в кошелёк без RPC»
- [ ] 12. `docker-compose.prod.yml`, Caddy с HTTPS, ежедневный бэкап базы; инструкция деплоя на VPS (выполняете вы) — тест: `make server-up` + `healthcheck`
- [ ] 13. Аудит субагентом `economy-auditor` — тест: нет замечаний уровня «критично»

## Затрагиваемые файлы
`server/src/{rpc,economy,auth,config}/*`, `server/tests/*`, `server/docker-compose*.yml`, `client/services/net/*`, `client/services/meta_cache.gd`, `client/meta/consent/*`

## Риски (детерминизм, сервер, производительность)
- Токены соцсетей никогда не принимаются без серверной проверки.
- Миграции хранилища только новыми версиями.
- Данные — на сервере в России (152-ФЗ).

## Обучение игрока
Нет новой игровой механики; окно согласия — при первом запуске.

## Готово, когда
Все 5 способов входа работают на тестовых аккаунтах, `make test-server` и `make lint` зелёные, сервер поднят на VPS.
