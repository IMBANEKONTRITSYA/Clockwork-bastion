# ADR-001. Стек: Godot 4.7 + Nakama + PostgreSQL

Статус: принято · Дата: 2026-11-17

## Контекст
Мобильная 2D-игра под Android с онлайн-экономикой, рейтингами, ивентами и режимом напарников. Команда — один разработчик и Claude Code. Нужен открытый движок без отчислений, лёгкий APK и сервер с готовыми аккаунтами, лидербордами и хранилищем.

## Решение
- Клиент: Godot 4.7.x, GDScript со строгой типизацией. Тесты — GUT.
- Сервер: Nakama (TypeScript-модули) + PostgreSQL в Docker Compose за Caddy. Тесты — Jest.
- Проверка забегов: тот же код симуляции, запущенный headless Godot (`validator/`).
- Покупки: RuStore Pay SDK (только сборка RuStore); платежи проверяет сервер. Сборка Google Play — без покупок.
- Реклама: Yandex Mobile Ads SDK (rewarded) через свой Android-плагин; награды по серверному подтверждению.
- Вход: гость (device id) + VK ID, Яндекс ID, Google, почта.
- Рынок и всё, что из него следует, — ADR-003.
- Ошибки — Sentry; аналитика — свои события в PostgreSQL + Metabase.
- CI — GitHub Actions.

## Почему не другое
- Unity: тяжелее сборка и редактор, условия лицензии менялись; для 2D-гиперказуала избыточен.
- Firebase/PlayFab: удобно, но привязка к вендору, сложнее серверная проверка забегов и хранение данных в нужной стране.
- Свой сервер с нуля: много работы на аккаунтах, лидербордах и сессиях, которые в Nakama уже есть.

## Последствия
- Логика боя пишется один раз (GDScript) и работает и на клиенте, и в валидаторе.
- Нужна дисциплина детерминизма — см. ADR-002 и `.claude/rules/simulation.md`.
- Сервер нужно держать самим: VPS в России (152-ФЗ).
