# Server RPC

RPC: $ARGUMENTS

1. Прочитай `.claude/rules/server.md` и существующие RPC в `server/src/rpc/` — повторяй их структуру.
2. Опиши контракт: вход (схема), выход (новое состояние), коды ошибок, лимиты, идемпотентный ключ.
3. Тесты сначала (`server/tests/rpc/<name>.test.ts`): успех, повтор с тем же ключом, превышение лимита, недостаточно средств, подделанный вход, параллельные вызовы.
4. Реализация в `server/src/rpc/<name>.ts`: сессия → валидация → лимиты по серверному времени → изменение только через `ledger` → ответ.
5. Регистрация в `server/src/main.ts`.
6. Клиент: метод в `client/services/net/` с таймаутом и понятной ошибкой; UI обновляется из ответа сервера, а не «оптимистично».
7. Проверка: `make test-server`, `npm run lint`, вызови субагента `economy-auditor`.
