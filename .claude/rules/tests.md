# Правила для тестов

- Клиент — GUT: файлы `test_*.gd` в `client/tests/<раздел>/`, класс `extends GutTest`. Сервер — Jest: `*.test.ts` в `server/tests/`.
- Структура: Arrange → Act → Assert, один сценарий — один тест. Имя описывает поведение: `test_reverse_stops_mechanism_for_45_ticks`.
- Для симуляции тесты строят состояние явно (сетка, шестерни, зерно), гоняют N тиков и проверяют целые числа точно — без «примерно».
- Тест детерминизма: один журнал → одинаковый хэш состояния на клиенте и в валидаторе. Эталонные журналы — `client/tests/fixtures/runs/`.
- Моки — только для внешних систем (сеть, RuStore, Яндекс Рекламная сеть, время сервера). Свой код не мокаем.
- Не ослабляй проверки, чтобы тест прошёл. Если поведение изменилось намеренно — скажи об этом явно и обнови `docs/design/core-rules.md`.
