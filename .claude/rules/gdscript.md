# Правила GDScript и сцен

- Статическая типизация везде: переменные, параметры, возвращаемые значения. В настройках проекта предупреждения о нетипизированном коде включены как ошибки.
- Порядок в файле: `class_name`, `extends`, сигналы, enum, константы, `@export`, публичные поля, приватные (`_name`), `_ready`/`_process`, публичные методы, приватные методы.
- Связь вверх по дереву — сигналами; вниз — вызовами. Глобальные синглтоны (autoload) — только сервисы из `client/services/` и `GameState`.
- Сцены маленькие и переиспользуемые; одна сцена — одна ответственность. Пути к нодам — через `@onready var x: T = %UniqueName`.
- Тексты для игрока — только `tr("KEY")`, ключи в `client/i18n/strings.csv` (ru, en).
- Числа баланса не хардкодим: читаем ресурсы из `client/data/`, которые генерирует `make data`.
- Производительность на слабых телефонах: пулы снарядов и эффектов, без `new()` в `_process`, частицы на GPU с ограничением количества.
- Магазин определяется флагом сборки: `Store.current()` → `rustore` | `gplay` (feature tags экспорта). Любой экран или кнопка покупки за деньги — только при `Store.has_payments()`; в `gplay` вместо магазина за деньги — магазин за алмазы и ролики.
- Сетевые вызовы — только через `client/services/net/` (обёртка над клиентом Nakama), с таймаутом и понятной ошибкой для игрока.
